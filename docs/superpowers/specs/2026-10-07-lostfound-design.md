# L&F 失物招领系统 · 设计文档

- **版本**：v0.1.0（草案 → 待用户审查）
- **日期**：2026-10-07
- **状态**：设计已经头脑风暴逐节确认（流程 / 规则 / 视觉 / 落地细节均已获批准），待书面规格审查
- **产物**：网站（公示 + 登记 + 认领 + 积分 + 隐藏后台）＋ L&F 现场 iPad PWA ＋ 硬件部署方案

---

## 0. 摘要

为学校 L&F（失物招领）角落设计的**真实落地系统**：一台锁定的 iPad 跑 PWA 作为现场操作台，配合编号投递柜与二维码引导牌；师生用自己手机扫码打开网页完成登记与认领。核心闭环「捡到 → 登记 → 入库 → 公示 → 认领 → 核销出库 → 积分发放」，以**延时发放 + 分级核验 + 全程留痕**抑制刷分与冒领。中英双语，视觉与学校在线门户同源。

## 1. 背景与目标

**现状痛点**：失物堆放无人管理、找回靠翻堆、登记打字慢造成排队、无激励机制、存在「自导自演刷积分」的隐患。

**设计目标**（成功标准）：

1. 每件物品从进门到出门都有系统记录，可追溯（谁登记、谁认领、何时出库）。
2. 捡到者登记全程 ≤ 2 分钟、不打长字；失主认领路径 ≤ 3 步。
3. 积分只能通过「物品被真实认领」获得，刷分在经济学与规则上均不划算。
4. G6-8（无手机）与 G9+（有手机）都能顺畅完成全流程。
5. 看起来像「学校官方做的」—— 门户同源配色、克制、无 AI 生成感。

**明确不做**（YAGNI）：微信小程序、电子锁柜、人脸识别、多校区、家长通知。

## 2. 用户与角色

| 角色 | 说明 | 使用端 |
|---|---|---|
| 捡到者（G9+，有手机） | 扫码登记、获积分 | 手机网页 + iPad 确认 |
| 捡到者（G6-8，无手机） | iPad 直办登记 | iPad PWA |
| 失主 | 浏览公示、申请认领、取回 | 手机网页 或 iPad 直办 |
| 管理员 | 复核高价值认领、处理异常、发兑换、看数据 | 隐藏后台 /admin（桌面优先） |
| 所有学生 | 查积分、逛积分商城 | 手机网页 / iPad |

**硬性场景约束**：G6-8 年级学生不能用手机 —— 一切流程必须有 iPad 直办路径；iPad 是公共屏幕，空闲态只显示公开信息。

## 4. 核心闭环流程（双路径）

### 4.1 路径一 · 手机路径（G9+ 及所有有手机者）

1. **扫码登记**：扫投递柜上的引导二维码 → 网页登记（拍照、描述、拾获地点、类别、价值档、本人学号+姓名+班级）。
2. **获得凭证**：系统分配「N 号格」+ 6 位投递核销码，显示在手机上（认领券样式）。
3. **放入编号格**：物品投进对应格子。
4. **iPad 确认入库**：在 iPad 上扫手机上的码（或输 6 位码）→ 大屏显示「已入库 ✅」。
5. **自动公示**：物品出现在公示列表 —— 照片+描述+地点+时间全公开；捡到者只显示**姓名+班级**（学号永不公开）。
6. **申请认领**：失主在列表找到物品 → 填认领申请（学号+姓名+一句话描述）→ 普通物品自动通过并生成**限时领取码**；高价值物品进入人工复核。
7. **iPad 核销出库**：失主在 iPad 输/扫领取码 → 确认出库 + **拍照存证** → 取走物品。
8. **积分发放**：出库完成那一刻，系统自动给捡到者积分（延时发放）。

### 4.2 路径二 · iPad 直办（G6-8 及所有无手机者）

- **登记 = 入库，一步完成**：iPad 点「我捡到了东西」→ iPad 拍照 → 点选标签（类别/地点/价值，全程不打字）→ 填学号+姓名+班级 → 大字显示「请放入 N 号格」→ 点「我已放入」→ 入库完成。
- **认领 = 核验 + 出库，一步完成**：iPad 点「我要找物品」→ 浏览公示 → 选物品 → 答认领信息 → 普通物品当场核验通过、拍照存证、取走；高价值转人工复核。
- **兑换**：iPad 上以学号+姓名查询积分、发起兑换 → 生成「待发放订单」，管理员定期发实物。

### 4.3 两路径一致性

两条路径写同一个数据库，公示、积分、后台、审计完全一致，不存在两套账。

## 5. 身份、积分与防作弊

### 5.1 身份与账号

- **学号 = 唯一账号**（7 位数字，如 9031622）。登记/认领/兑换时填学号+姓名+班级；学号格式校验（7 位数字）+ 二次确认。
- 对外公示与任何公开 API **永不返回学号**；捡到者/认领者对外仅显示姓名+班级。
- 网站凭学号可查积分（知道学号本身是一道弱门槛，积分非高敏数据）。

### 5.2 积分规则（数值可在后台调整）

| 事件 | 积分 | 说明 |
|---|---|---|
| 物品被成功领取（出库完成） | 捡到者 +10 | 延时发放：登记不发分，认领成功才结算 |
| 高价值物品被领取 | 捡到者 +25 | 钱包/手机/平板/耳机/证件类 |
| 失主感谢打赏 | 1–10 分 | 失主从自己余额自愿转给捡到者 |
| 登记但无人认领 | 0 分 | 只计入「贡献次数」展示，防滥登记刷分 |
| 兑换 | -对应分值 | 生成待发放订单 |
| 每人每月上限 | 100 分 | 超出后当月不再累加，后台可调 |

### 5.3 防作弊五层防线

> 前提：公示信息全透明，「凭隐藏细节自动核验」不成立，因此防线如下。

1. **分级核验**：普通物品极简认领（自动通过）；高价值物品必须人工复核（管理员比对内容物描述与实物）后才发领取码。
2. **出库留痕**：每次核销 iPad 拍照存证 + 认领人学号入档，冒领可追责、纠纷可回溯。
3. **异常自动标记**：登记后极短时间内被认领（秒领）、同一认领人反复出现、同一对登记/认领配对过频、相似描述重复登记 → 自动黄标，进管理员抽查队列。
4. **经济学防线**：奖品定价使「扔一件真物品换积分」永远亏损（积分价值远低于物品价值）。
5. **规则防线**：延时发放 + 月度上限 + 登记不加分。

## 6. 认领核验（分级）

| 档位 | 判定 | 认领流程 | 出库 |
|---|---|---|---|
| 普通 | 登记时自选或默认 | 自动通过，发限时领取码（默认 48h 有效） | iPad 核销 + 拍照存证 |
| 高价值 | 由类别自动判定（证件/钱包/电子），管理员可调整 | 进入人工复核队列 → 管理员通过后才生成领取码 | 同上 |

- 领取码过期未使用 → 物品回到「待认领」，可再次申请。
- 认领被拒绝（复核不通过）→ 记录原因，物品重新公示。

## 7. 积分商城与兑换

- 商城在网站与 iPad 端均可浏览；兑换 = 扣分 + 生成「待发放订单」。
- 管理员按订单定期发放实物并标记完成；库存不足自动下架。
- 首批奖品池（示例，由管理团队实际运营）：文具套装 40 分、打印额度 20 页 25 分、小卖部 5 元券 50 分。

## 8. 视觉设计系统

**路线**：hallmark custom（学校色锚定）· 风格族 modern-minimal · 基调 utilitarian + 校园归属。
**受众/任务/基调**（推断已披露并确认）：全校师生 G6-12+员工；手机端=登记/公示/认领，iPad=现场直办核销；官方工具感、像「学校官方做的」。

| navy | #00458A | 深藏青：kiosk 空闲屏背景、票据头部 |
| bar | #005EBB | 顶栏/导航底色 |

| muted | #5E6B76 | 次要文字 |
| rule | #D9E2EE | 分隔线/描边 |
| paper | #F2F6FB | 页面底色（不用纯白） |
| surface | #FBFDFF | 卡片表面 |
| cyan | #CAF0FE | 信息提示、焦点软色、kiosk 强调 |

| 插画三色 | #7AC143 / #29ABE2 / #F7941E | 仅类别圆点与图形点缀，不大面积使用 |

### 8.2 字体

- 正文/界面：**Lato**（Latin，自托管 400/700/800，与学校门户同源）+ **PingFang SC / Noto Sans SC**（中文系统栈）
- 数字/编码：**IBM Plex Mono**（自托管 400/600/700）—— 格号、领取码、学号、时间戳、统计数字一律 mono
- 纪律：标题不斜体；字阶 12/13/15/17/22/28；正文 ≥14px（移动端 15px 基准）

### 8.3 签名元素 —— 「格位牌 & 认领券」

- **格位牌**：物品卡上的 mono 大号格号标签（像柜子上的号码牌），列表/详情/出库全程一致。
- **认领券**：领取码渲染为带撕边打孔的票据（虚线 + 两侧打孔圆 + 大号 mono 编码 + 有效期），是整个产品被记住的元素。
- 空状态/成功态文案遵循「指路不抒情」：错误不道歉、空屏即邀请。

### 8.4 反 AI 味纪律（hard gates）

不编造数据/评价；不重绘浏览器/手机壳 chrome；所有颜色与字体走命名 token；标题不用斜体；单屏只做一个编排动效；尊重 prefers-reduced-motion；焦点态一等公民；文案用动词具体说事（「保存更改」而非「提交」）。

## 9. 界面结构与响应式

### 9.1 手机端屏幕（375 基准，底部 Tab：公示 / ＋登记 / 我的积分）

1. **公示首页**：顶栏（logo + 中/EN + 积分入口）→ 本周统计条（mono 数字）→ 搜索 + 类别筛选 chips（带彩色圆点）→ 物品卡列表（照片占位、标题、地点时间、格位牌、状态 chip、捡到者姓名+班级）
2. **登记拾获**：三步（拍照 → 描述/类别/地点/价值 → 学号+姓名+班级确认）→ 成功页 = 认领券样式（N 号格 + 6 位核销码 + 指引）
3. **认领申请**：物品详情（全细节公开）→ 一句话描述 + 学号姓名 → 通过即出**认领券**（领取码 + 有效期）
4. **我的积分**：学号查询 → 余额 + 流水 + 贡献次数；积分商城（兑换 → 待发放订单提示）

### 9.2 iPad 端状态机（横屏优先，PWA 全屏）

```
空闲屏（深藏青，公开信息only）
├─ 我捡到了东西 → 拍照 → 点选标签 → 学号姓名 → 大字格号 → 「我已放入」→ 入库完成
├─ 我要找物品 → 浏览公示 → 选物品 → 核验 →
│    ├─ 普通：确认出库 + 拍照存证 → 完成
│    └─ 高价值：转人工复核提示（附领取码输入入口，复核通过后可核销）
├─ 扫码/输码 · 投递确认（手机路径 step4）→ 入库完成
├─ 扫码/输码 · 核销出库（领取码 6 格大键盘 + 扫码 + 认领信息确认卡 + 拍照存证）
└─ 兑换直办（学号+姓名 → 余额 → 选奖品 → 待发放订单凭证）
```

- 空闲屏组成：顶栏（logo、连接状态、时钟、中/EN）+ 两大动作卡（利用横宽）+ 右侧「今日动态」归还播报 + 底部致谢条。

### 9.3 响应式与大屏适配（硬性要求）

- 断点：**320 / 375 / 414 / 768 / 1024 / 1194 / 1366** 全部人工截图验证；无横向滚动；双行可点文字禁止。
- kiosk：横屏优先（834×1194 目标，左侧动作/输入、右侧信息确认的分栏）；竖屏降级可用。
- 网站桌面（≥1024）：公示列表变 3 列网格 + 右侧「我的积分 / 商城」侧栏。
- 后台：桌面优先，最小支持 1024。

## 10. 技术架构

- **托管**：Cloudflare Workers（API + 静态资产，wrangler 单仓库部署），D1 SQLite 存储 —— 与既有项目同架构，零成本、自带 HTTPS/CDN。
- **前端**：原生 HTML/CSS/JS（无框架），CSS 命名 token（生产 OKLCH）；PWA = manifest + Service Worker（静态壳离线缓存，断网时 kiosk 显示「网络不可用，请稍后重试」并保留未提交草稿于 localStorage）。
- **二维码扫描**：jsQR/ZXing **本地打包**（不经 CDN），iPad 摄像头权限首次授予；所有扫码入口都有**手动输码兜底**。
- **API 草案**：

| 端点 | 方法 | 说明 |
|---|---|---|
| /api/items | GET | 公示列表（公开字段不含学号） |
| /api/items/:id | GET | 物品详情 |
| /api/report | POST | 登记拾获（multipart 照片+字段）→ 返回格号+投递核销码 |
| /api/kiosk/confirm-drop | POST | iPad 投递确认（码） |
| /api/claims | POST | 认领申请 → 自动通过/进复核，返回领取码或排队号 |
| /api/kiosk/verify-pickup | POST | 领取码校验 → 认领信息 |
| /api/kiosk/fulfill | POST | 确认出库（存证照片）→ 触发积分结算 |
| /api/points/:student_id | GET | 积分查询 |
| /api/tips | POST | 失主感谢打赏 |
| /api/rewards · /api/redemptions | GET/POST | 商城与兑换 |
| /api/admin/* | 全部 | 口令 + X-Admin-Token：复核队列、黄标抽查、积分调整、兑换发放、过期处理、看板 |

- **数据模型（核心表）**：`identities`(student_id PK, name, class) · `items`(code LF-YYYY-NNNN, title, desc, category, location, photo, value_tier, slot_no, status, registered_by, via, timestamps) · `claims`(item, claimant, note, status, pickup_code, expiry, evidence_photo) · `points_ledger`(student, delta, reason, ref) · `rewards` · `redemptions` · `risk_flags`(subject, reason, resolved) · `admin_audit`(action, target, at)。
- **物品状态机**：registered（待投递确认）→ in_stock（已入库/公示中）→ claim_pending（认领中/复核）→ ready（待领取，持有有效领取码）→ returned（已归还）｜ expired（过期，学期末捐赠）。
- **安全**：学号不出公开 API；速率限制（同 IP/同学号每日登记上限）；上传照片压缩+尺寸限制；后台口令 + token，全部操作写审计；错误信息不泄露内部细节。

## 11. 硬件与现场部署

- **投递柜**：12 格起（2 大格 A4 尺寸 + 10 小格），柜门贴大号 mono 数字（与界面格位牌同款视觉）；提供**可打印格位标签模板**。
- **引导牌**：A5 亚克力二维码牌（「捡到东西？扫码登记」+ 短链 `/r`），iPad 旁贴「投递确认 / 领取核销」指引。
- **iPad**：防盗支架 + 导管锁；引导式访问锁定单应用；首启配置清单（摄像头权限、PWA 安装、自动登录、屏幕常亮、亮度、横屏锁定）。

## 12. 上线与运营

- 域名：先挂现有 Cloudflare 域名子域试运行，后续可换学校官方域名；push 即部署。
- 种子数据：演示物品若干（公示、流程演示用）。
- 上线检查清单：7 断点截图、全流程冒烟（登记→确认→认领→核销→积分）、安全自测（学号泄漏/越权/限流）、后台口令就位。
- 运营节奏：管理团队每周查看后台（复核队列/黄标/兑换订单）；物品 30 天未认领 → 列表标记「即将过期」；学期末统一捐赠并归档。

## 13. 边界与错误处理

| 场景 | 处理 |
|---|---|
| 断网 | kiosk 显示离线横幅；登记草稿存 localStorage，恢复后一键重提 |
| 格子已满 | 提示「投递柜已满」，指引大件/特殊情况贴条联系管理员；后台可增格 |
| 领取码过期 | 物品回到「待认领」，可重新申请 |
| 认领纠纷 | 出库记录（学号+照片+时间）作为凭据，管理员调解 |
| 高价值复核超时 | 队列置顶提醒；管理员不在线时物品保持 in_stock |
| 学号输错 | 格式校验 + 姓名/班级交叉展示确认 |
